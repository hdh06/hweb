# 2.1
**Question:** What is the purpose of system calls?
**Answer:** Programming Interface to the OS services. For user to indirectly interact with the kernel and its services such as resource allocation, accounting, security and protections,...

# 2.4
**Question:** What is the purpose of system programs?
**Answer:** Provide a convienient environment for program development and execution. Ex: GNU ultilities for Linux
(Extra) Example use case of system programs: 
- File management 
- Status information 
- File modification 
- Programming-language support 
- Program loading and execution
- Communications (among processes, users and systems)

# 2.5
**Question:** What is the main advantage of the layered approach to system design? What are the disadvantages of the layered approach?
**Answer:** 
- Advantages: Simple to construct and debug (due to modularity, we only need to consider one layer at the time when developing/debugging)
- Disadvantages: Hard to appropriately define the layers, tends to be less efficient with more layers (more overheads to communicate between layers)

# 2.8
**Question:** How could a system be designed to allow a choice of operating systems from which to boot? What would the bootstrap program need to do?
**Answer:**
- When the system started it first run the BIOS (first bootloader) in the ROM to load in the (second) bootloader (UEFI/GRUB)
- The system use a bootstrap program/bootloader to locate the kernel of the correct OS 
- (Extra) Then the kernel load into memory and started, initialize the hardware and mounted the root file system of that OS of choice

# 2.11
**Question:** Describe how you could obtain a statistical profile of the amount of time a program spends executing different sections of its code. Discuss the importance of obtaining such a statistical profile.
**Answer:** By using per-process statistic of the counters, we can record a current elapsing time before and after the code sections. Then we use the different between the two to compute the time spends on a section. This is important because we can analyzing the performace to improve it or remove bottlenecks. 

# 2.15
**Question:** What are the two models of interprocess communication? What are the strengths and weaknesses of the two approaches?
**Answer:** Shared memory and Message passing. 
- Shared memory: Faster, no overhead but complicate to implement, can be easy messed up and need synchonization to work properly
- Message passing: More overhead so it slower but it is easier to use and memory safe
